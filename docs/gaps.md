# Named gaps

Where a feed does not exist, the platform says so rather than inventing a
number. These are the gaps a Dean will see named on the dashboard.

| Gap | Why it matters | Source to connect |
|---|---|---|
| Course coverage by term | Which required courses have no confirmed instructor next term | my.harvard / SIS |
| Section fill and enrollment | Where demand exceeds capacity | SIS |
| Teaching load per faculty member | Sections taught against norms and leave | SIS + faculty roster |
| TF and TA allocation | Teaching support against enrollment | GSAS / FAS TF records |
| PhD admissions and yield | Cohort size against the announced cuts | GSAS |
| Space and scheduling | Where a leave or vacancy breaks a sequence | FAS Registrar |
| Curriculum and programme review | New course and programme approvals in flight | FAS Registrar |
| Budget vs actual by division | Can we afford this? | FAS Finance |
| Position control | Which lines are authorised, filled, frozen, eliminated | Aurora |
| Funding source per hire | Endowment, grant, provost, dean's office | FAS Finance |
| Live case status by process | Tenure, promotion, searches, leaves, reappointments in flight | Aurora / Appointments Office log |

## What each gap needs

For each gap, the platform requires:

1. A named source system
2. A data owner
3. A refresh cadence
4. A reconciliation method
5. A provenance label

Until all five exist, the gap stays named.
